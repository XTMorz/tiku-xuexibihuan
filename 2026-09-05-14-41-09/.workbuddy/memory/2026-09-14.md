## 完成：计算分析题「待核对」支持人工判定对错

### 需求

计算分析题 / 综合题作答后，自动比对只要不完全一致就落到「待对照」，用户希望在这种情况下能**手动选择对 / 错**。

### 改动

- `app.js`
  - `submitPracticeAnswer`：计算分析题提交时保存 `autoCorrect` 与 `judged`（'correct' | 'wrong' | 'pending'）；自动比对未命中时 `judged='pending'`，且**不计入累计正确数 `q.correct`**、不进错题本
  - 新增 `judgeEssayAnswer(q, verdict)`：手动判定入口，同步修正 练习计分 `_answers`、`q.correct`、`q.isWrong`、`history` 末条，并 `saveState + scheduleSync + updateBadges + renderPracticeCard`

  - 新增 `isPendingJudgement(pa)` / `judgeBarHTML()`；`renderFeedback` 非 choice 分支重写：pending 用琥珀色 `待核对`，已判定显示 `已判定「答对了/答错了」`，判断题仍显示 回答正确/错误
  - `renderPracticeCard`：结算面板把 `pending` 的题单独统计，正确率只算已判定的；有待核对时出现「去核对这 N 题」按钮（跳到第一道 pending 题）
  - 顶栏进度状态条支持「待核对」琥珀色显示
  - 帮助文案更新为「提交→对照参考答案后点答对了/答错了手动判定」
- `styles.css`
  - 新增 `.feedback.pending`、`.judge-bar / .judge-hint / .judge-actions / .judge-btn`（含 ok/no/undo 与 active 态）、`.finish-pending`、`.btn.warn`
  - ≤480px：判定按钮 flex 撑满一行，方便手机点
  - 暗色模式下 pending/判定区改用半透明叠色，避免浅底浅字
- 同步：判定结果走原有 Gist 自动同步（5s debounce）

### 教训

## 完成：修复「云同步拉取失败 Unterminated string in JSON」

### 现象

拉取报错：`Unterminated string in JSON at position 416539 (line 1 column 416540)`。

### 根因（实锤）

**GitHub Gist 接口对单个文件只返回前 1MB 内容**，并在文件对象上置 `truncated: true`
（官方文档：https://docs.github.com/en/rest/gists/gists "Truncation" 章节）。

题库 payload 已经超过 1MB（教材 `book.sourceText` 占大头：中文教材解析出来的原文几百 KB，
多本累加轻松破 1MB）。旧代码 `gistGet()` 直接返回 `files['qb-library-sync.json'].content`，
从不判断 `truncated`，于是拿到的是被砍掉一半的 JSON → `JSON.parse` 在 1MB 字节对应的字符位置（≈416539）报
“Unterminated string”。**上传一直没问题**（Gist 存储不设 1MB 上限，只是读接口截断），所以只有拉取挂。

### 修复

- `app.js` `gistGet()` 重写：
  1. `!file.truncated` → 直接用 `content`（快路径，不发额外请求）
  2. `truncated` → 先试 `file.raw_url`（带 commit sha，不会命中旧缓存）
  3. raw_url 失败 → 再试 `GET /gists/{id}` + `Accept: application/vnd.github.raw`（带 Token，一定过 CORS）
  4. 每条路都用 `isCompleteJSON()` 校验，取不到完整内容就抛**中文可读错误**（说明 1MB 上限 + 给出处理建议）
- 新增 `syncPayloadStats()` / `formatBytes()` / `renderSyncSize()`：同步面板显示总体积、教材原文占比、
  相对 1MB 的进度条；>1MB 红色提示、>85% 琥珀色提示。只在面板打开时计算（避免后台白序列化 1MB+）
- `syncPush()`：显示上传体积；新增 `_lastPushedState` 指纹去重，无改动不重复上传 1MB+
- `syncPull()`：JSON.parse 兜底错误提示，失败时先提醒「设置 → 导出题库」备份本机数据
- `index.html` 加 `#sync-size-hint`；`styles.css` 加 `.sync-size`（含 warn/danger 变体 + 暗色模式半透明叠色）

### 测试

- 自测扩到 **80 / 80 通过**（新增 T10–T14，用打桩的 `window.fetch` 模拟 GitHub 各种返回）
  - T10 截断→改走 raw_url 拿到完整内容 / T11 raw_url 失败→退回 API raw 媒体类型
  - T12 两条路都不通→抛中文错误（含 1MB 说明 + 同步设置建议）/ T13 未截断走快路径且不发多余请求
  - T14 体积统计、>1MB 判定、面板渲染与 danger/warn 样式
- 截图核对同步面板 warn / danger / 手机端

### 教训

- **用 Gist 当存储，读的时候必须处理 `truncated`**——上传成功 ≠ 读得回来。
- 「position 416539」这种奇怪的截断点其实是 1MB 字节换算成字符数（中文 2~3 字节/字符），
  遇到 JSON 报 Unterminated string 又找不到语法错误时，先怀疑内容被截断。
- 无头 Edge `--window-size=430` 实际视口是 492（Windows 下有最小窗口宽度），
  量出来 `docSW == vw` 说明没有真实溢出，截图右侧被裁是假象，别误判成 CSS bug。

## 完成：多选题可多选 + 分题型判分 + 练习按题型/提醒筛选

### 需求

1. 多项选择题只能选一个选项（bug）——原来 `renderPracticeCard` 的选项点击逻辑对所有题型都
   「先清空全部选中，再选中当前项」，多选题被强制单选。
2. 按考试规则判分：单选 1.5 分 / 多选 2 分（全对满分、少选得相应分值、多选错选不答 0 分）/
   判断 1 分（不扣分）/ 计算分析题共 22 分（按步骤给分）。
3. 练习可以按「题型」和「提醒（缺答案/缺解析）」筛选。

### 改动（app.js）

- 新增统一题型入口 `resolveQtypeRaw(q)`：single/multi/judge/calc/essay。
  - 关键修复：被解析器误标成 `single` 但答案就是多个字母（如 ABD）的题 → 自动纠正为 multi，
    否则永远只能选一个。
  - 题干含「多选/多项」也识别为 multi；calc/essay/judge 直接返回（避免对长题干做无用正则）。
- 答案解析 `normalizeAnswerKeys()`：支持 "ABD" / "A、B、D" / "A B C" / "A. 文本" / 选项全文；
  旧 `normalizeAnswerKey()` 改为它的薄封装（删除了旧的重复实现——同脚本里同名函数声明会后者覆盖前者，
  第一版就因为残留旧实现导致 typeKey 报错）。
- 判分 `gradeChoiceAnswer()`：multi 全对=满分，少选=按 `选对个数/正确个数` 比例给分（保留两位小数），
  含错选/多选/不答=0；single/judge 完全一致才得分。
- 分值 `fullScoreOf()`：`OBJECTIVE_SCORE = {single:1.5, multi:2, judge:1}`；
  主观题 `SUBJECTIVE_SECTION_SCORE = {calc:22, essay:22}` 按「同章节同题型题数」均分（带缓存，
  `saveState` 时失效，避免大题库反复全表扫描）；题目自带 `q.score` 时优先。
- 多选 UI：`renderChoiceOptions()` 支持 toggle 多选、已选计数、提交后漏选项标 `missed`（琥珀虚线）、
  错选标 `wrong`、正确项标 `correct`；多选题只选 1 项提交时先 `confirm` 确认。
- 提交 `submitPracticeAnswer()`：`_practiceAnswer` 增加 `userKeys/correctKeys/score/fullScore/level/typeKey`；
  少选（partial）不算答对但计部分分，且**进错题本**（未掌握）；待核对仍不计分不进错题本。
- 人工判分 `judgeEssayAnswer(q, verdict, manualScore)`：新增 `verdict='score'` 支持任意部分得分，
  判定条增加「部分得分」输入框（0~满分，步长 0.5），满分/0 分/撤销同步修正得分、q.correct、错题本、history、_answers。
- 结算面板：主数字改为 `得分/满分`（分），显示得分率、答对题数、正确率，并按题型给分项小计（进度条）。
- 练习筛选：`startPractice()` 支持 `#practice-qtype`（题型）与 `#practice-flag`（题况提醒）两级筛选，
  下拉里直接带数量（`refreshPracticeFilters()`，按签名增量刷新）；
  「重做错题/练习收藏题」快捷入口会先复位这两级筛选。
- `questionCardHTML` 的题型 tag 改用 `resolveQtypeRaw`，与练习页一致。

### 改动（index.html / styles.css）

- 练习栏新增两个 select（题型 / 题况），手机端换行两列、按钮独占一行。
- 新样式：`.multi-hint`（多选提示条+已选计数）、`.practice-option.correct.missed`（漏选）、
  `.partial-hint`（少选提示）、`.feedback-line.score-line`、`.judge-partial`（部分得分录入）、
  `.finish-breakdown`（分项小计）、多选题选中态用方角勾号；题型 tag 在手机端改为独立一行
  （绝对定位在窄屏会被裁掉）。多选答案 "AD" 的 `.ca-key` 改为自适应宽度胶囊。

## 修复：「重做错题 / 练习收藏题」点了没反应

### 根因

- `#btn-practice-wrong` / `#btn-practice-fav` 在**错题本 / 收藏页**（`data-view="wrong|fav"`），
  而 `#practice-area` 在**练习页**（`data-view="practice"`）。快捷入口只改了隐藏视图里的 select
  并把练习卡片渲染进隐藏容器，页面不跳转 → 用户看着就是「点了没反应」（只有一条不起眼的 toast）。
  这个 bug 从第一版就存在，不是本次改动引入的。
- 顺带发现：`switchTab('practice')` 里调用的 `renderPractice()` **全项目没有定义**（.bak 里就有），
  一切到练习页就抛 ReferenceError；因为视图切换在那行之前已完成，所以平时看不出来，
  但练习卡片不会随切页重绘。

### 修复（app.js）

- `switchTab('practice')`：`renderPractice()` → `renderPracticeCard()`。
- `startPractice()` 改为返回 boolean（true=组卷成功；false=题池为空/被筛选清空，只弹了提示），
  错题本为空时的提示改成更明确的「错题本是空的，先去做几道题吧」。
- `quickPractice(range)`：复位题型/题况筛选 → `startPractice()` → **组卷成功才 `switchTab('practice')`**；
  无错题/无收藏时停留在原页面，只弹提示，不会误跳。

### 测试

- `_selftest.js` 扩到 **176 项断言全过**：新增 G 组 14 项（错题本/收藏页点击后自动跳练习页、
  组卷范围与题数、筛选复位、无错题时不误跳、切练习页不再抛错、返回值语义）。
- 截图 `quick-wrong-before / quick-wrong-after`：点击前停在错题本页，点击后自动跳到练习页，
  范围显示「仅错题本」、第 1/2 题、多选题渲染正常。

### 教训

- **「操作入口在 A 页、结果渲染在 B 页」的按钮必须显式切页**，只弹 toast 用户会当成没反应。
- 截图/自测脚本从 `test_files/` 恢复到项目目录再跑，改完 `test_files/_shot.js` 后必须先重新
  `gen_test.py`（它会把测试文件拷回去），否则测的还是旧脚本、mode 匹配不上就静默走默认流程。

## 修复：刷题时不该显示「我的笔记」，改为作答后再显示

### 需求

练习卡片里「我的思考」的笔记框一直是常显的 —— 笔记里往往写着要点、结论甚至答案，
边做题边摆在眼前等于抄答案。要求：作答前不显示笔记，提交作答后再显示。

### 改动

- `app.js` 抽出 `renderNoteArea(q, answered)`（原先是写死在 `renderPracticeCard` 的模板里）：
  - **未作答**：不渲染 textarea，`q.note` 内容一个字都不出现在卡片里；
    但该题若确实记过笔记，保留一条 `.note-area.locked` + `.note-locked-hint` 提示
    （「本题你记过笔记，作答后会显示在这里」），否则用户会以为笔记丢了。没有笔记则完全不占位。
  - **已作答**：渲染原文本框并回填 `q.note`，输入仍 400ms debounce 自动保存。
- 判定口子在 `renderPracticeCard` 里用 `!!userAns`（即 `q._practiceAnswer` 是否存在）→
  「跳过」走的 `goNext()` 会 `delete q._practiceAnswer`，所以跳过的题回来仍是锁定态，
  只有真正提交过答案才解锁。
- `styles.css` 新增 `.note-area.locked` / `.note-locked-hint`（沿用原虚线分隔 + 莫兰迪灰字）。

### 测试

- `_selftest.js` 扩到 **191 项断言全过**：新增 H 组 15 项
  - 无笔记+未作答→不占位 / 有笔记+未作答→只有提示、无 textarea、**笔记原文不出现在 innerHTML**（防泄题）
  - 作答后→textarea 出现且原文回填、锁提示消失、编辑仍自动落盘
  - 跳过后回看第 1 题→笔记重新锁上
  - 多选 / 计算分析题同样受控
- 截图 `note-locked / note-none / note-shown`（桌面端 + 430px 手机端）核对。

### 教训

- 这类「防泄题」的 UI 改动，断言不能只看 DOM 里有没有那个元素，**必须断言笔记原文没有出现在
  容器 innerHTML 里**——否则一旦模板里把内容渲染进别的节点（如 `data-*`、`title`）就漏检了。
